# Инструкция по запуску системы

## 1. Что должно быть установлено

Нужен Node.js с поддержкой встроенного модуля `node:sqlite`.

Проверить можно так:

```bash
node -e "require('node:sqlite'); console.log('sqlite ok')"
```

Также должны быть установлены зависимости проекта:

```bash
npm install
```

В проекте используется библиотека `ws`.

## 2. Запуск сервера

Открой первый терминал в папке проекта:

```bash
cd ~/Документы/VSCODE2/JavaScript/messaging_system_websocket
```

Запусти сервер:

```bash
npm run server
```

Сервер создаст:

- один `primary` process;
- `os.cpus().length` WebSocket-воркеров;
- один отдельный `db-worker`;
- SQLite-файл `data/messages.sqlite`.

В терминале должны появиться строки вида:

```text
Server primary ... is running
Starting ... WebSocket workers on port 8080
Starting one DB worker with SQLite file ...
DB worker ... started
Server worker ... listening on port 8080
```

Важно: сервер должен оставаться запущенным.

## 3. Запуск основных 10 клиентов

Открой второй терминал в той же папке проекта:

```bash
cd ~/Документы/VSCODE2/JavaScript/messaging_system_websocket
```

Запусти 10 клиентских процессов:

```bash
npm run clients
```

Что произойдёт:

1. `client-master.js` создаст 10 процессов `client-worker.js`.
2. Имена будут сгенерированы автоматически:

```text
client-0
client-1
...
client-9
```

3. Каждый клиент подключится к серверу и зарегистрируется.
4. После регистрации всех 10 клиентов начнётся отправка сообщений.
5. Каждый клиент отправит `100000` сообщений случайным другим клиентам.
6. В конце будет проверка:

```text
sent=1000000
received=1000000
match=true
pairMatch=true
```

Если после `sent=1000000/1000000` система ещё ждёт, это нормально.
Она догоняет доставку сообщений, которые могли попасть в WebSocket-буферы или offline-очередь.

Каждый запуск `client-master.js` получает свой `runId`.
Основные клиенты считают в итоговую статистику только сообщения текущего запуска.
Это нужно, чтобы старые offline-сообщения из БД или сообщения от ручных клиентов
не ломали проверку `sent === received`.

## 4. Быстрый тест

Для быстрой проверки без ожидания полного миллиона сообщений:

```bash
npm run clients:small
```

Этот режим запускает те же 10 клиентов, но отправляет меньше сообщений.

Ожидаемый финал:

```text
match=true
pairMatch=true
```

## 5. Демо offline-режима

Для демонстрации случайных отключений и переподключений:

```bash
npm run clients:offline-demo
```

В этом режиме клиенты чаще отключаются и переподключаются.

Идея проверки:

- клиент отключился;
- другие клиенты продолжают отправлять ему сообщения;
- сервер сохраняет эти сообщения в БД;
- клиент переподключается;
- сервер достаёт накопленные сообщения из БД и доставляет их;
- клиент отправляет `message-ack`;
- сервер удаляет доставленные сообщения из БД.

Финал также должен быть:

```text
match=true
pairMatch=true
```

## 6. Запуск ручного внешнего клиента

Ручной клиент нужен для дополнительного требования задания.
Он не создаётся через `client-master.js`, а запускается отдельно.

Сначала сервер должен быть запущен:

```bash
npm run server
```

После этого можно открыть новый терминал и запустить ручного клиента:

```bash
npm run client:manual -- manual-1 client-0,client-1
```

Где:

- `manual-1` — имя ручного клиента;
- `client-0,client-1` — список целей по умолчанию.

Внутри ручного клиента доступны команды:

```text
send client-0 hello
send client-1 test message
stats
targets client-2,client-3
quit
```

Пример:

```text
send client-0 hello
```

Это отправит сообщение клиенту `client-0`.

## 7. Запуск двух ручных клиентов

Терминал 1:

```bash
npm run client:manual -- manual-1 manual-2
```

Терминал 2:

```bash
npm run client:manual -- manual-2 manual-1
```

После этого из первого клиента можно написать:

```text
send manual-2 hello
```

Из второго:

```text
send manual-1 hi
```

Важно: нельзя запускать два ручных клиента с одним и тем же именем.
Например, два процесса `manual-1` будут конфликтовать.

## 8. Где хранится состояние

Offline-сообщения хранятся в SQLite:

```text
data/messages.sqlite
```

Состояние ручных клиентов хранится в папке:

```text
.client-state
```

Там сохраняются счётчики ручного клиента и список полученных `messageId`.

## 9. Как остановить систему

Остановить сервер:

```text
Ctrl+C
```

Остановить `client-master`:

```text
Ctrl+C
```

Остановить ручного клиента:

```text
quit
```

или:

```text
Ctrl+C
```

## 10. Частые проблемы

### Сервер не запущен

Если клиент пишет ошибки подключения, сначала проверь, что сервер запущен:

```bash
npm run server
```

### Имя ручного клиента уже занято

Если запустить два ручных клиента с одним именем, сервер закроет одно из соединений.

Правильно:

```bash
npm run client:manual -- manual-1 manual-2
npm run client:manual -- manual-2 manual-1
```

Неправильно:

```bash
npm run client:manual -- manual-1 manual-2
npm run client:manual -- manual-1 client-0
```

### После отправки всех сообщений система ещё ждёт

Это нормально.

Пример:

```text
sent=1000000/1000000
received=866350/1000000
```

Это значит, что все сообщения уже отправлены клиентами, но часть ещё доставляется.
Финал будет только после:

```text
received=1000000/1000000
pairMismatches=0
```

### received стало больше, чем sent

Если видно что-то вроде:

```text
sent=1000000/1000000
received=1000004/1000000
```

значит в старой версии в статистику попали лишние сообщения:

- старые offline-сообщения из `data/messages.sqlite`;
- сообщения от ручного клиента `manual-*`;
- сообщения, оставшиеся после предыдущего незавершённого запуска.

В текущей версии это закрыто через `runId`: каждый новый запуск считает только свои
сообщения. Старые offline-сообщения всё равно будут получены и подтверждены через
`message-ack`, но в статистику теста не попадут.
